# OpenClaw 主機強化 (Host Hardening)

## 概觀

評估並強化執行 OpenClaw 的主機，將其調整至使用者定義的風險承受度，同時確保存取不中斷。將 OpenClaw 安全工具視為核心訊號，但將作業系統 (OS) 強化視為一套獨立且明確的步驟。

## 核心規則

- 建議使用頂尖模型（如 Opus 4.5, GPT 5.2+）執行此技能。代理人應自我檢查目前模型，若等級較低則建議切換；但不應阻礙執行。
- 任何會改動狀態的動作皆 **必須** 取得明確核准。
- 在未確認使用者連線方式前，不可修改遠端存取設定。
- 優先採用可還原、分階段的變更，並附帶回滾 (Rollback) 計畫。
- 絕不可宣稱 OpenClaw 會自動更改主機防火牆、SSH 或 OS 更新；它不會這麼做。
- 若角色/身分不明，僅提供建議。
- 格式規範：每組使用者選項皆必須編號，以便使用者透過單一數字回覆。
- 建議進行系統級備份；嘗試驗證其狀態。

## 工作流程（請依序執行）

### 0) 模型自我檢查（非阻塞）

開始前，檢查目前模型。若低於頂尖等級，建議切換。不阻礙執行。

### 1) 建立上下文（唯讀）

在詢問前，嘗試從環境中推斷 1–10 項資訊。若需確認，優先使用簡單、非技術性的問題。

依序確定：
1. 作業系統與版本、容器 vs 主機。
2. 權限等級（root/admin vs 一般使用者）。
3. 存取路徑（本地主控台、SSH、RDP、Tailnet）。
4. 網路曝險（公網 IP、反向代理、隧道）。
5. OpenClaw 閘道器狀態與繫結位址。
6. 備份系統與狀態（如 Time Machine、系統映像檔、快照）。
7. 部署背景（本地 Mac App、無頭閘道器主機、遠端閘道器、容器/CI）。
8. 磁碟加密狀態 (FileVault/LUKS/BitLocker)。
9. OS 自動安全性更新狀態。
10. 使用模式（本地工作站 vs 遠端伺服器 vs 其它）。

首先詢問一次執行唯讀檢查的權限。若獲准，預設執行檢查，僅針對無法推斷或驗證的項目提出問題。不要詢問執行時期或指令輸出中已顯而易見的資訊。權限請求應為單一句子，後續需要的資訊以無序清單列出。

若必須詢問，請使用非技術性提示：
- 「您使用的是 Mac、Windows PC 還是 Linux？」
- 「您是直接登入機器，還是從另一台電腦連線？」
- 「這台機器可以從公網連線，還是僅限家庭/內部網路？」
- 「您有啟用備份嗎？目前狀態是否正常？」
- 「磁碟加密有開啟嗎？」
- 「您如何使用這台機器？（例如：與助理共用的個人電腦、專用伺服器等）」

僅在了解系統上下文後，才詢問風險設定檔。

### 2) 執行 OpenClaw 安全審計（唯讀）

作為預設唯讀檢查的一部分，執行 `openclaw security audit --deep`。僅在使用者要求時提供替代方案：
1. `openclaw security audit`（較快，非探針式）
2. `openclaw security audit --json`（結構化輸出）

提議套用 OpenClaw 安全預設值（編號）：
1. `openclaw security audit --fix`

明確說明 `--fix` 僅會收緊 OpenClaw 的預設值與檔案權限，**不會** 更改主機防火牆、SSH 或 OS 更新策略。

### 3) 檢查 OpenClaw 版本/更新狀態（唯讀）

執行 `openclaw update status`。回報目前頻道與是否有可用更新。

### 4) 確定風險承受度

要求使用者選擇或確認風險狀況與任何需要的開放服務/連接埠。提供建議的設定檔作為選用預設值（編號）：
1. **家用/工作站平衡 (最常見)**：開啟防火牆並使用合理預設值，遠端存取限制在 LAN 或 Tailnet。
2. **VPS 強化**：預設拒絕傳入的防火牆、極少開放連接埠、僅限金鑰登入的 SSH、禁止 root 登入、自動安全性更新。
3. **開發者便利**：允許較多本地服務，明確的曝險警告，仍會進行審計。
4. **自訂**：使用者定義的約束條件。

### 5) 產生改善計畫 (Remediation Plan)

提供包含以下內容的計畫：
- 目標設定檔、目前狀況摘要、與目標的差距。
- 包含精確指令的逐步改善步驟。
- 存取保持策略與回滾方案。
- 風險與潛在的連線中斷情境。
- 最小權限說明與憑證衛生建議。

在進行任何變更前，務必顯示計畫。

### 6) 提供執行選項

1. 幫我執行（引導式、逐步核准）
2. 僅顯示計畫
3. 僅修復關鍵問題
4. 匯出指令供稍後執行

### 7) 依核准執行

針對每個步驟：顯示精確指令、解釋影響與回滾方式、確認存取權維持、遇意外輸出即停止並詢問。

### 8) 驗證與回報

重新檢查防火牆、連接埠、遠端存取與 OpenClaw 安全審計。交付最終報告。

## 必要的確認 (一律執行)

針對以下動作 **必須** 取得明確核准：
- 防火牆規則變更、開啟/關閉連接埠、SSH/RDP 組態變更。
- 安裝/移除套件、啟用/停用服務、使用者/群組修改。
- 排程任務或啟動持久化、更新策略變更、存取敏感檔案或憑證。

## 定期檢查

建議持續監控。使用 OpenClaw Cron 工具/CLI 來排程定期審計。**未經明確核准，不可建立排程任務**。

### 必要的排程提示 (一律執行)

在任何審計或強化流程後，明確提議排程並要求直接回應：
1. 「您想要透過 `openclaw cron add` 排程定期審計（如每日/每週）嗎？」

若使用者同意，詢問頻率、時間視窗與輸出位置。使用穩定且精確的任務名稱：
- `healthcheck:security-audit`
- `healthcheck:update-status`

## 記憶寫入 (Memory writes)

僅在使用者明確同意且工作階段為私有/本地工作區時，才將紀錄寫入記憶檔案。否則，提供一個經遮蔽且可供貼上的摘要。

遵循 OpenClaw 壓縮使用的持久記憶格式：
- 將持久性備註寫入 `memory/YYYY-MM-DD.md`。
- 包含檢查內容、關鍵發現、採取的行動、排程任務、關鍵決定以及執行的指令。
- **僅限附加 (Append-only)**：絕不覆寫現有條目。
- **遮蔽細節**：遮蔽敏感的主機詳情（使用者名稱、主機名稱、IP、序號、服務名稱、權杖）。
