# 外掛程式 SDK 與執行時期重構計畫

## 目標
讓每一個通訊頻道連線器（不論是內建或外部）都使用單一、穩定的 API。外掛程式將不再直接從 `src/**` 導入內容，所有的依賴皆透過 SDK 或執行時期 (Runtime) 處理。

## 架構設計（兩層架構）

### 1) 外掛程式 SDK (編譯時期，穩定且可發佈)
- **範圍**：類型定義 (Types)、輔助函數與組態工具。
- **特性**：不含執行時期狀態，無副作用。
- **內容**：包含 `ChannelPlugin` 類型、組態輔助函數、配對輔助工具、引導設定輔助工具等。

### 2) 外掛程式執行時期 (執行介面，注入式)
- **範圍**：所有觸及核心執行行為的功能。
- **存取方式**：透過 `OpenClawPluginApi.runtime` 存取，外掛程式禁止直接導入 `src/**`。
- **功能介面**：包含頻道文字切分、回覆派發、路由解析、配對處理、多媒體儲存、提及偵測以及群組原則解析等。

## 遷移計畫

- **階段 0：腳手架搭建**：引入 `openclaw/plugin-sdk`，並在 API 中加入 `runtime` 介面。
- **階段 1：橋接器清理**：將現有的 `core-bridge.ts` 替換為 `api.runtime`。
- **階段 2 & 3：遷移現有外掛程式**：依序遷移 Matrix, MS Teams 等外掛程式，驗證回覆與輸入中指示的語義一致性。
- **階段 4：iMessage 外掛程式化**：將核心中的 iMessage 邏輯移動至 `extensions/imessage` 並使用新 API。
- **階段 5：強制執行**：加入 CI 檢查，禁止從 `src/**` 導入 `extensions/**`。

## 成功標準
- 所有頻道連線器皆為使用 SDK + Runtime 的外掛程式。
- `src/**` 中完全沒有 `extensions/**` 的導入語句。
- 外部外掛程式可在無需核心原始碼的情況下進行開發與更新。
