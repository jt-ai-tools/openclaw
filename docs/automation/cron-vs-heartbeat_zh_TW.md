# Cron vs Heartbeat：如何選擇？

心跳機制 (Heartbeat) 與排程任務 (Cron) 都能讓您按計畫執行任務。本指南將協助您根據需求選擇正確的機制。

## 快速決策指南

| 使用情境                             | 推薦機制             | 原因                                      |
| ------------------------------------ | ------------------- | ---------------------------------------- |
| 每 30 分鐘檢查一次收件匣             | **Heartbeat**       | 可與其它檢查合併處理，且具備上下文感知能力 |
| 早上 9 點準時發送日報                | **Cron (隔離)**     | 需要精確的時間點                          |
| 監控行事曆中即將到來的活動           | **Heartbeat**       | 非常適合作為週期性的狀態意識              |
| 執行每週深度分析                     | **Cron (隔離)**     | 獨立任務，可使用不同的模型                |
| 20 分鐘後提醒我                      | **Cron (主會話)**   | 具備精確時間的單次提醒                    |

## 心跳機制 (Heartbeat)：週期性意識
心跳偵測在 **主工作階段** 內以固定間隔執行（預設 30 分鐘）。

**優點：**
- **合併檢查**：一個心跳回合可以同時檢查郵件、行事曆與通知，節省 API 呼叫次數。
- **上下文感知**：代理人擁有完整的歷史紀錄，能判斷哪些事緊急，哪些可以緩辦。
- **沈默回覆**：若無事發生，代理人回覆 `HEARTBEAT_OK`，使用者不會看到任何訊息。

## 排程任務 (Cron)：精確排程
排程任務在 **精確的時間點** 執行，且可在隔離的工作階段中執行而不影響主對話。

**優點：**
- **時間精確**：支援標準的 Cron 表達式與時區。
- **環境隔離**：在 `cron:<jobId>` 中執行，不會洗版主對話歷史。
- **模型覆寫**：可為特定任務指定更廉價或更強大的模型。
- **單次執行**：支援使用 `--at` 指定未來的精確時間戳記。

## 決策流程圖

1. **任務需要「精確」的時間點嗎？** (例如：準時 9:00)
   - 是 → 使用 **Cron**。
   - 否 → 繼續下一步。
2. **任務需要與主工作階段隔離嗎？**
   - 是 → 使用 **Cron (隔離)**。
   - 否 → 繼續下一步。
3. **任務可以與其它週期性檢查合併嗎？**
   - 是 → 使用 **Heartbeat** (新增至 `HEARTBEAT.md`)。
   - 否 → 使用 **Cron**。

## 總結
最高效的配置是 **兩者併用**：使用 **Heartbeat** 處理例行性的輕量監控，使用 **Cron** 處理精確的時間點任務（如報告發送）與單次提醒。
