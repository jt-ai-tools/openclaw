# 執行核准 (Exec approvals)

執行核准是讓沙箱化的代理人在真實主機（閘道器或節點）上執行指令的 **配套 App / 節點主機防護欄**。可以將其視為一種安全互鎖機制：只有當策略、允許清單與（選用的）使用者核准皆達成共識時，指令才被允許執行。

如果配套 App UI **不可達**，任何需要提示的請求將由 **詢問備援方案 (ask fallback)** 決定（預設為拒絕）。

## 適用位置

執行核准會在執行主機上本地強制執行：
- **閘道器主機**：閘道器機器上的 `openclaw` 程序。
- **節點主機**：節點執行器（macOS 配套 App 或無頭節點主機）。

## 設定與儲存

核准設定儲存於執行主機的本地 JSON 檔案中：
`~/.openclaw/exec-approvals.json`

## 策略選項

### 安全性 (`exec.security`)
- **deny**：封鎖所有主機執行請求。
- **allowlist**：僅允許位於允許清單中的指令。
- **full**：允許所有執行（等同於提升權限模式）。

### 詢問 (`exec.ask`)
- **off**：永不提示。
- **on-miss**：僅在允許清單不匹配時提示。
- **always**：每個指令皆提示。

## 允許清單 (每代理人獨立)

允許清單是 **按代理人區分** 的。模式匹配採用 **不分大小寫的 Glob 匹配**。
匹配對象應為 **二進位檔路徑**。

範例：
- `~/Projects/**/bin/peekaboo`
- `/opt/homebrew/bin/rg`

## 自動允許技能 CLI

啟用後，已知技能所參考的可執行檔在節點上會被視為已加入允許清單。

## 安全二進位檔 (僅限標準輸入)

`tools.exec.safeBins` 定義了一組 **僅限標準輸入 (stdin-only)** 的二進位檔（例如 `jq`），它們可以在允許清單模式下 **無需** 額外條目即可執行。這些工具拒絕位置參數，僅能對傳入串流進行操作。

預設安全工具：`jq`, `grep`, `cut`, `sort`, `uniq`, `head`, `tail`, `tr`, `wc`。

## 核准流程

當需要提示時，閘道器會向操作者客戶端廣播請求。執行工具會立即回傳一個核准 ID。
使用者可以選擇：
- **Allow once (僅允許一次)**：立即執行。
- **Always allow (一律允許)**：加入允許清單並執行。
- **Deny (拒絕)**：封鎖執行。

## 轉發核准至通訊頻道

您可以將核准提示轉發至任何通訊頻道，並透過 `/approve <ID> <動作>` 進行遠端核准。

## 系統事件

執行生命週期會以系統訊息形式顯示於工作階段中：
- `Exec running`（若執行時間超過閾值）
- `Exec finished`
- `Exec denied`
