# 技能建立者 (Skill Creator)

此技能為建立高效技能提供指引。

## 關於技能 (About Skills)

技能是模組化、自成一體的套件，透過提供專業知識、工作流與工具來擴展 Codex 的能力。可以將它們想像成特定領域或任務的「引導指南」—— 它們將 Codex 從一個通用代理人轉變為具備特定程序知識的專業代理人，而這些知識是任何模型都無法完全擁有的。

### 技能提供的內容

1. **專業工作流**：針對特定領域的多步驟程序。
2. **工具整合**：處理特定檔案格式或 API 的指令。
3. **領域專業知識**：公司特定知識、Schema、業務邏輯。
4. **隨附資源**：用於處理複雜且重複任務的腳本、參考文件與資產。

## 核心原則

### 簡潔是關鍵

上下文視窗 (Context window) 是公共資源。技能必須與 Codex 需要的所有其它內容共用上下文：系統提示詞、對談歷史、其它技能的詮釋資料以及使用者的實際請求。

**預設假設：Codex 已經非常聰明。** 僅新增 Codex 尚未擁有的上下文。審視每一項資訊：「Codex 真的需要這段解釋嗎？」以及「這段文字值得它所消耗的 Token 成本嗎？」

優先使用簡潔的範例，而非冗長的解釋。

### 設定適當的自由度

根據任務的脆弱性與變異性來調整精確度等級：

- **高自由度（文字指令）**：當有多種可行方法、決策取決於上下文，或可透過啟發式方法引導時使用。
- **中自由度（帶參數的偽代碼或腳本）**：當存在偏好的模式、允許部分變異，或組態會影響行為時使用。
- **低自由度（特定的腳本，極少參數）**：當操作脆弱且易出錯、一致性至關重要，或必須遵循特定順序時使用。

## 技能剖析 (Anatomy of a Skill)

每個技能包含一個必要的 `SKILL.md` 檔案以及選用的隨附資源：

```
技能名稱/
├── SKILL.md (必要)
│   ├── YAML 前端詮釋資料 (必要)
│   │   ├── name: (必要)
│   │   └── description: (必要)
│   └── Markdown 指令 (必要)
└── 隨附資源 (選用)
    ├── scripts/          - 可執行程式碼 (Python/Bash 等)
    ├── references/       - 視需求載入上下文的說明文件
    └── assets/           - 輸出中使用的檔案 (模板, 圖示, 字型等)
```

### 隨附資源 (選用)

#### 腳本 (`scripts/`)
適用於需要確定性可靠性或會被重複編寫的任務。例如：`scripts/rotate_pdf.py`。優點是節省 Token 且具備確定性。

#### 參考文件 (`references/`)
旨在根據需求載入上下文的說明文件。例如：資料庫 Schema、API 文件、公司政策。優點是保持 `SKILL.md` 精簡，僅在 Codex 判斷需要時才載入。

#### 資產 (`assets/`)
不載入上下文，而是用於 Codex 產出的輸出結果中。例如：品牌圖誌、簡報模板、前端樣板。

## 漸進式揭露設計原則 (Progressive Disclosure)

技能使用三層載入系統來高效管理上下文：

1. **詮釋資料 (Metadata)**：名稱與描述 —— 始終存在於上下文中。
2. **SKILL.md 主體**：當技能觸發時載入。
3. **隨附資源**：由 Codex 視需求載入。

### 漸進式揭露模式

保持 `SKILL.md` 主體在 500 行以內。當接近限制時，將內容拆分至不同檔案，並在 `SKILL.md` 中明確描述讀取時機。

**模式 1：帶有參考的高階指南**
在 `SKILL.md` 中提供快速入門，並連結至 `FORMS.md`, `REFERENCE.md` 或 `EXAMPLES.md`。

**模式 2：領域專屬組織**
針對多個領域的技能，按領域組織檔案（如 `finance.md`, `sales.md`），Codex 僅讀取相關領域的文件。

## 技能建立流程

1. 透過具體範例了解需求。
2. 規劃可重複使用的內容。
3. 初始化技能（執行 `init_skill.py`）。
4. 編輯技能（實作資源並撰寫 `SKILL.md`）。
5. 打包技能（執行 `package_skill.py`）。
6. 根據實際使用情況進行迭代。

### 命名規範
- 僅限小寫字母、數字與連字號。
- 優先使用動詞開頭的短語（如 `gh-address-comments`）。

### 撰寫 SKILL.md 指引

#### Frontmatter (YAML)
僅包含 `name` 與 `description`。描述內容是觸發機制的關鍵，應包含功能說明與使用情境。

#### Body (Markdown)
使用祈使句或不定詞撰寫指令。

## 打包技能

完成開發後，使用 `scripts/package_skill.py` 進行驗證與打包。驗證過程會檢查 YAML 格式、命名慣例與描述完整性。打包後會產生一個 `.skill` 壓縮檔。
